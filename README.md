# dyna_barn — PufferLib navigation env(s) targeting the DynaBARN benchmark

Two PufferLib Ocean envs for evaluating mobile-robot navigation against the
[DynaBARN](docs/dyna_barn.md) benchmark protocol:

| Env | Purpose |
|---|---|
| `train_env/` | Curriculum-driven procedural generation. Random start/goal, sampled obstacle count + motion profile per episode. Online trajectory generation in C — every episode is fresh. |
| `eval_env/` | DynaBARN-style fixed evaluation. Start (0, 11) → goal (0, −9). Worlds drawn from the published `[order, speed, std]` parameter bins (easy / medium / hard). Same code as `train_env/` but with the eval distribution and a fixed protocol. |

Both envs share the same robot model, LiDAR sensor simulation, and observation
shape so a single trained policy works in both.

## Shared spec

- **Robot**: Clearpath Jackal — differential drive, `v ∈ [−0.5, 2.0]` m/s,
  `w ∈ [−π, π]` rad/s. 500 × 430 × 250 mm footprint. Acceleration limits
  `a_max=10` m/s², `α_max=20` rad/s² (paper `base_local_planner_params.yaml`).
- **Sensor**: 2D LiDAR, 720 beams, 270° FOV, 30 m max range, simulated by raycast
  against moving cylinder obstacles.
- **Obstacles**: cylinders, radius 0.5 m, deterministic waypoint trajectories
  generated by polynomial fit (paper Algorithm 1) — linear interpolation between
  waypoints, no inter-obstacle collisions, non-reactive to the robot.
- **Arena**: 24 × 24 m walled (train); 3-walled "room" open on +x (paper eval).
- **Observation**: 4100 floats — `[costmap_64x64, v, w, gx_body, gy_body]`.
  Egocentric body-frame occupancy grid (LingBot-inspired) + ego twist + goal vector.
- **Action**: `(v, w)` continuous 2-vector in `[-1, 1]` mapped to physical envelope.
- **Reward** (training-time): multi-scale Gaussian goal attraction (3 scales,
  weights 0.3/0.3/0.4) + dense per-step obstacle repulsion `β·exp(-(d/σ)²)`.
  No success bonus, no per-event collision penalty, no termination on goal
  or collision — episodes always run the full 800 ticks (80 s at dt=0.1).
- **Episode termination** (train): full 80 s (truncation only).
- **Episode termination** (paper eval): on goal, collision, or timeout.

## Headline result (2026-05-17)

Single policy `e7sadb3v` (500M steps, beta=10) trained on procedural
worlds, evaluated on the 60 published DynaBARN worlds (600 trials):

| Difficulty | Success | Collision | Timeout |
|---|---|---|---|
| Easy | 55.5 % | 35.5 % | 9.0 % |
| Medium | 44.5 % | 50.0 % | 5.5 % |
| Hard | 34.0 % | 61.5 % | 4.5 % |
| **Overall** | **44.7 %** | 49.0 % | 6.3 % |

Reported SOTA (from `docs/dyna_barn.md`): LfH-CP 30.83 %, E2E 18.5 %.
Our result beats reported LfH-CP by **+13.9 pp**.

## Pipelines

- **Train**: `python -m pufferlib.pufferl train dyna_train ...` (env config
  in `dyna_train/dyna_train.ini`).
- **Standalone rollouts** (post-training): `./dyna_train --traj X.bin --load
  ckpt.bin --episodes N` dumps a binary trajectory file; the same env reads
  the same .ini so distributions match.
- **Bake**: `tools/bake_traj_parquet.py X.bin X.parquet` (binary → parquet,
  broadcasts per-episode flags to every tick).
- **Render**: `tools/render_train_dist_webms.py` (procedural eval) or
  `tools/render_eval_gifs.py` (paper 60-worlds eval). Both parallelised
  via `ProcessPoolExecutor` with spawn-context (24-worker default).
- **Paper eval**: `bash run_eval_published.sh <ckpt.bin> 10 600` runs
  10 trials × 60 worlds, writes `summary.json` + per-world parquets +
  optional WebMs.
